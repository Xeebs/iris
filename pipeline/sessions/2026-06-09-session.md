## 3. Key finding — ~80 API route modules are implemented but never mounted

`apps/api/src/routes/*.ts` exports route factories that have passing unit tests but are
**never referenced in `apps/api/src/server.ts`**, so their endpoints return 404 at runtime.
The autonomous pipeline generates `route + test` but does not wire the route into `createApp`.

**Impact:** unit-test counts look healthy while the product's HTTP surface is largely
unreachable. Confirmed-broken user-facing flows found this session:
- `/api/v1/permissions/*` — dashboard admin permissions page (fixed, batch 1).
- `/api/v1/workflows` — dashboard workflows page (fixed, batch 2).
- `/api/v1/api-keys` — **MCP API key issue/rotate/revoke**, depended on by the e2e auth
  fixtures (`tests/e2e/fixtures/auth-mocks.ts`). **Still unmounted** — needs care (see §5).

**Detection one-liner** (re-run to refresh the list):
```bash
for f in apps/api/src/routes/*.ts; do
  fn=$(grep -oE "export function (create[A-Za-z]+Routes|make[A-Za-z]+Router)" "$f" | awk '{print $3}' | head -1)
  [ -z "$fn" ] && continue
  grep -q "$fn" apps/api/src/server.ts || echo "UNMOUNTED: $fn ($(basename "$f"))"
done
```

Recorded as memory `project-unmounted-routes` and as the Layer-77 High task in `queue.md`.

## 4. Recommendations / safe process for the remaining routes

1. **Mount in small batches (5–10), never all at once.** A single constructor doing I/O at
   construction, or a route-prefix collision, breaks server boot → CI red. `tsc` build catches
   signature/type errors locally; only the **integration CI job** (boots server, hits `/health`)
   catches boot failures, and there is no local Docker here to boot-test.
2. **Per route:** read its own test file for the prefix it asserts (`app.route('<prefix>', …)`),
   confirm that prefix isn't already mounted / doesn't collide, then add
   `authed.route('<prefix>', createXRoutes(sql))` in `createApp`.
3. **`SqlFn`-typed factories** (entity-search, usage, mcp-tools, etc.) need a cast — the postgres
   `Sql` client is runtime-compatible but nominally differs from `Promise`. Pattern used:
   `createXRoutes(sql as unknown as Parameters<typeof createXRoutes>[0])`.
   `Sql` / `SqlClient` / `ReturnType<typeof postgres>` factories take `sql` directly.
4. After each batch: `pnpm --filter @iris/api build` → commit → push → `gh run watch` the run,
   confirming the *Integration Load Tests* job is green before the next batch.

### Special cases (do NOT bulk-mount)
- `api-key-management.ts` — second arg `masterSecret: string`. **First confirm the MCP
  auth-verify path uses the same key store/secret**, else you mint keys auth can't validate.
  No existing master-secret env is wired in `server.ts` today.
- `compliance-audit.ts` — odd param type `Parameters<typeof generateAuditReport>[0]`; check it.
- `mcp-resource-discovery.ts`, `mcp-streaming.ts`, `query-explanation.ts` — take **no args** `()`.
- Watch prefix families that already have a mounted sibling: `/metrics` (computed-metrics →
  `/metrics/computed`), `/query-analytics` (query-execution-plans), `/search*`, `/admin/*`,
  `/entities` (entity-* routes), `/webhooks` (webhook-admin / webhook-dlq).
