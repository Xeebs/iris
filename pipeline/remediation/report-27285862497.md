## Root cause

- `RetrievalOptions.relevanceCutoff` is documented in `packages/semantic-core/src/retrieval.ts` (incl. the `RETRIEVAL_RELEVANCE_CUTOFF` env default) **but was never implemented** — the function body at HEAD never reads it.

- `compress()` (`packages/compression/src/pipeline.ts`) only truncates at the 2000-token budget; ~600-token responses fit, so nothing is dropped. Its `query` option is literally "reserved for future relevance scoring".
- Side effect of attempt 1 (6c64c32, BM25 fix): retrieval recall went up, fattening responses further.
